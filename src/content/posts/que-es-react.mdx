<Concept title="Definición y problema que resuelve">

**React es una librería de JavaScript para construir interfaces de usuario**, desarrollada por Meta. Se incorpora al proyecto como una dependencia más y se empieza a usar de inmediato, sin necesidad de una configuración compleja.

Antes de React, construir una interfaz implicaba manipular el DOM a mano: crear cada elemento con `document.createElement`, añadir y quitar *listeners* manualmente, y actualizar a mano cada parte de la pantalla cuando un dato cambiaba. Si esa misma información se mostraba en tres sitios distintos, había que recordar actualizar los tres. Esto se vuelve difícil de mantener a medida que la aplicación crece.

React cambia el enfoque: en lugar de decirle paso a paso cómo actualizar la pantalla, el desarrollador describe qué debe verse para cada estado de los datos, y React se encarga de aplicar los cambios necesarios. Ya no hay que actualizar manualmente cada lugar donde se muestra un dato.

</Concept>

<Concept title="JSX">

JSX es la sintaxis que utiliza React; no son lo mismo. Es una extensión de JavaScript que permite escribir elementos de interfaz con una notación similar a HTML, directamente dentro del código, en lugar de construir cada elemento con `document.createElement`.

Dentro de las llaves `{ }` de un bloque JSX se puede escribir cualquier expresión de JavaScript: una variable, el resultado de una función, una condición. Eso es lo que permite que la interfaz cambie según los datos.

```jsx
// sin JSX — DOM API estándar
const div = document.createElement('div');
div.textContent = 'Hola';
document.body.appendChild(div);

// con JSX — la variable se inserta directo
const nombre = 'Ana';
const elemento = <div>Hola, {nombre}</div>;
```

<RuleCheck rule="Usar JSX para describir la interfaz; nunca manipular el DOM directamente con document.createElement o innerHTML">
  **Usar en mis reglas de código:** Describir la interfaz siempre con JSX, no con DOM API directa.
</RuleCheck>

</Concept>

<Concept title="DOM virtual">

El DOM real es lo que el navegador dibuja en pantalla. React mantiene además una copia interna llamada DOM virtual. Cuando un dato cambia, React no redibuja toda la pantalla de cero: compara la versión anterior del DOM virtual con la nueva, identifica exactamente qué partes cambiaron, y actualiza solo esas en el DOM real. Este proceso de comparación se llama *reconciliation*.

En la práctica, el desarrollador solo describe el resultado final que quiere ver, y React calcula la forma más eficiente de llegar a ese resultado.

</Concept>

<Concept title="Anatomía de un componente">

Un componente de React es una función de JavaScript que retorna JSX. Ese retorno debe tener un único elemento raíz que envuelva al resto; no se pueden retornar varios elementos sueltos uno al lado del otro.

Un componente puede declarar estado local con el hook `useState`. Un *hook* es una función especial de React (siempre empieza con `use`) que da acceso a capacidades como el estado o el ciclo de vida del componente. El estado es un dato que, cuando cambia, hace que React vuelva a ejecutar la función y actualice lo que se muestra en pantalla.

```jsx
import { useState } from 'react';

function Contador() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
  }

  return (
    <div>
      <p>{count}</p>
      <button onClick={handleClick}>Sumar</button>
    </div>
  );
}
```

<MarginNote>
  **Para recordar:** cuando se llama a `setCount`, React vuelve a ejecutar la función `Contador` completa con el nuevo valor de `count` y actualiza solo lo que cambió en pantalla.
</MarginNote>

<RuleCheck rule="Cada componente es una función JS que retorna JSX con un único elemento raíz. Todo estado local se declara con useState; nunca variables sueltas fuera del hook">
  **Usar en mis reglas de código:** Componentes como funciones con raíz única; estado local siempre con `useState`.
</RuleCheck>

</Concept>

<Concept title="Composición y props">

Una interfaz compleja se construye combinando componentes más pequeños. Un mismo componente puede usarse varias veces dentro de la misma pantalla; lo único que cambia entre cada uso es la información que recibe.

Esa información se llama **props** (abreviatura de *properties*): son los datos que un componente recibe desde el que lo usa, igual que los parámetros de una función. Según las props que recibe, el mismo componente muestra algo distinto.

```jsx
function Tarjeta({ titulo, precio }) {
  return (
    <div>
      <h3>{titulo}</h3>
      <p>{precio}</p>
    </div>
  );
}

// mismo componente, distintas props
<Tarjeta titulo="Mouse" precio="10€" />
<Tarjeta titulo="Teclado" precio="25€" />
```

<MarginNote>
  **Para recordar:** las props son de solo lectura. Un componente nunca modifica las props que recibe; si necesita cambiar algo que viene de afuera, el padre debe exponer una función para solicitar ese cambio.
</MarginNote>

<RuleCheck rule="Las props son de solo lectura: el componente nunca las muta. Si se necesita un cambio externo, el padre expone un callback y el hijo lo llama">
  **Usar en mis reglas de código:** Props de solo lectura; cambios externos siempre mediante callback del padre.
</RuleCheck>

</Concept>
